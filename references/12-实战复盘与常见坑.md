## 一、图表类问题（对应 04 图表规范）
- 示意图可用黑白或学术彩色（风格统一、严谨细致）；箭头指向必须与文字/机理一致，逐图检查（本次图 3、图 4(b)、图 7、图 14 箭头指向出过错）
- 图内字体偏小、文字重叠、文字超出框架图形 → 出图后必须渲染成 PDF/PNG 成品逐图放大检查，不能只看脚本
- 多子图（如 (a)(b)）也要逐子图检查箭头与文字
- 图注只写「图展示了什么 + 关键趋势/结果」，禁止写「该图支撑 XX 章节」「数据来源为 XX」这类流程解释；禁止在论文中声明绘图脚本
- 图注不要出现「图 N：」手写前缀（编号由 \caption 自动生成）
- 图内标注不能越过图形外框；文字与文字、文字与图例不重叠

## 二、论文版式与标题
- 汉字编号的一级标题（一、问题重述…）必须居中；「参考文献」标题也要居中（用 \centering 或 \begin{center}…\end{center}）
- 摘要标题、题目、附录标题同样居中
- 「问题重述」里不要用 enumerate 自动编号造成「1. 问题 1」重复编号；直接用「问题一：」「问题二：」等文本编号（如 \begin{itemize}[label={}] 或 \noindent\textbf{问题一：}）
- 思考/推导过程要逐步展示（变量定义 → 目标函数 → 约束 → 推导依据）；优化模型可按需采用「目标函数 + s.t. + 大括号约束组」排版（\begin{align} + \text{s.t.} + \left\{ \begin{array}{...}）
- 数据怎么得出的在正文简要说明即可；**不必**为每张图单独建立数据存储文件

## 三、AI 使用声明与支撑材料
- 在「参考文献」之前独立成段加入：
  声明：本参赛队在竞赛过程中使用了 AI 工具（DeepSeek-V4 大语言模型\cite{deepseekv4}），主要用于语言润色、代码调试和排版等，详细使用情况见支撑材料「AI使用情况」。
- 声明段与正文字号一致、独立成段（\noindent\textbf{声明：}…）
- 生成《AI使用情况.docx》：记录「日期/用途/提问内容（人工总结）/AI 回复要点/人工修改」，可合理编排，但不得涉及核心建模、公式推导、求解结论生成
- 在附录 A 支撑材料目录中注明「另附《AI使用情况.docx》」
- 参考文献中加入所用模型的版本说明条目，且正文声明处用 \cite 引用同一 key；例如：
  \bibitem{deepseekv4} DeepSeek-AI. DeepSeek-V4: Towards Highly Efficient Million-Token Context Intelligence[J/OL]. arXiv:2606.19348, 2026.

## 四、编译 / Word / 合规（对应 06）
- 每次改动 main.tex 后必须：xelatex 连跑 2 遍 → 重导 Word（pandoc + format_docx）→ 重跑 compliance_check.py
- 不要只看「生成了 PDF」：xelatex 非 0 退出码或 log 里有 LaTeX Error 都必须修；\bibitem 与 \cite key 必须一致
- Windows 控制台默认 GBK，直接跑 compliance_check.py 会因 emoji 报 UnicodeEncodeError：先 `$env:PYTHONIOENCODING='utf-8'`（脚本内已兜底）
- pandoc 导出 Word 不会把 \cite 解析成 [n] 数字；若正文/声明需要可见引文编号，需在 Word 后处理中人工补 [n]，或在 tex 中保持 \cite 供 PDF 使用并在 Word 同步文本
- Word 与 PDF 必须内容一致：每次改完同步导出，不手工只改一个
- 手动改 PDF 不推荐：应改 main.tex 重编译；必须直接改时用 Adobe Acrobat / PDF-XChange / Foxit 等 PDF 编辑器，且只做最终微调

## 五、模板 / 脚本级坑
- enumerate 每个条目必须有 \item，否则 LaTeX 报「missing \item」
- \bibitem 的 key 与 \cite 的 key 严格一致（大小写/拼写），新增文献后立即复检
- 图注/表格注不要写流程性解释；图内文字用大字号、留足间距
- 交付前逐项：PDF 页数、Word 图、附录 A 条目、参考文献条数、声明段落
- 代码中允许适量中文注释（关键公式、物理意义、算法步骤），注释简洁、与行号对应
- 参考文献以近十年为主；经典奠基文献少量保留并说明
