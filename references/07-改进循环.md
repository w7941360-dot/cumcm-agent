# 07 改进循环

> 借鉴 ARIS 原则：**正确性规则永远必须过；风格规则只是强默认，可商量。** 停止条件是 Type-A 全过 + 用户验收通过（Codex 不得自行宣告完成）。

## 第 0 层：求解阶段优化闭环（步骤 2~3 期间，Type-A 纪律）

> 适用：含硬指标/设计变量的优化题（详见 `references/02-建模选型.md` 求解治理、`references/11-带硬指标的设计优化.md`）。在进入论文写作与结果审计之前，先保证"搜索空间含解、代理不误导、范式不被锚定"。

```text
pilot：估计代理与全模型的单次成本（3~5 次），估算总耗时

for 每一种布局/设计范式:
    理论推导变量与边界
    生成全模型可行种子 或 理论上界（上界<额定目标 → 否决该范式）
    校准代理（排序相关≥0.9、假阳性=0；物理项不得随意省略）
    scan：代理搜索，保留 top-K、边界候选、多样性候选
    refine：全模型评估 + 局部优化
    若满足硬约束：
        提高效率/成本目标，做稳健性验证
    若不满足：
        一次只调整一个假设或变量组，记录到 run_registry，再进入下一轮
    若连续 N 轮(默认3)无可行候选，或功率/性能上界低于目标：
        返回建模选型，切换布局范式、物理模型或决策变量
```

### 纪律（每条都是 Type-A 可查项）
- 先用 3~5 次 pilot 评估估算总耗时，再决定扫描规模与 refine 次数上限
- **每轮只改变一个假设**，记录"假设—配置—输出—耗时—结论"到 `code/run_registry.json`
- 中断运行必须标记为 `aborted`，空文件不得视为结果，未完成不得命名 `final`
- 达到脚本数量或全模型评估预算后，**必须复盘范式**，不得继续堆变体
- **连续 N 轮不可行是"返回建模选型"的触发器，不是继续加密扫描的理由**
- 所有记录由 `scripts/solution_audit.py --mode optimization` 机器核对（范式切换、预算、空/中断误判）

## 第①层：事实 / 正确性（必须过）

### A1. 证据预检（Type-A，机器可查）
- 把摘要/结论里的关键数字整理成 `claims.json`，跑：
  `python scripts/evidence_check.py <工作区根目录> --batch claims.json`
- 全部 `verified` 才过；`path_missing` / `value_not_found` 必须修复（数字要么删掉，要么改到与结果一致）

### A0. 交付与优化审计（Type-A，机器可查，先于证据预检）
- 跑 `python scripts/solution_audit.py <工作区> --mode deliverable`：
  每问代码入口存在、结果文件存在且非空、官方附件非空且非原始模板、表头/列序/取值约束合规、硬约束由全模型结果满足；任一子问题缺失即 FAIL
- 优化题再跑 `python scripts/solution_audit.py <工作区> --mode optimization`：
  目标与硬约束并存、代理物理项清单、校准样本、范式切换、最佳可行解、预算、空/中断误判

### A2. 结论支撑
- 每个结论都有数据/图表/代码输出支撑
- 每个图表在正文有编号引用；题注与图中数据一致

### A3. 数值可信度（步骤3 的 5 项校验复核）
- Sanity / Consistency / Physical / Prediction / Evaluation

### A4. 灵敏度与稳定性（A 题硬指标）
- ≥1 项参数扫描或扰动分析，且正文有对应章节

### A5. 合规
- 页数（摘要≤1 页；正文（不含参考文献与附录）≤30 页，25 页最好）、匿名、公式渲染、图表引用、参考文献真实

## 第②层：质量 / 风格（Type-B，由用户判定）
1. 摘要是否 1 页内讲清"方法 + 具体数值结果"
2. 图表是否清晰易读（黑白可印刷、标签完整）
3. 语言是否精炼、无错别字/病句
4. 结构是否顺畅、逻辑是否自洽

## 验收契约逐条核对
- 打开 `PAPER_ACCEPTANCE_CONTRACT.md`（步骤6 定的验收标准），逐条打 ✔/✘
- 优化题同时打开 `SOLUTION_ACCEPTANCE_CONTRACT.md`（步骤1-2 定的求解标准），逐条打 ✔/✘
- 由**用户**做最终判定；未过项列出 → 修复 → 重编译 → 复验

## 常见失分点
- 只有模型没有求解、没有数值结果
- 模型与题目脱节（没回答题目要的量）
- 优化题：搜索空间本身无解仍硬扫、代理删掉决定可行性的物理项、某问没有结果文件仍交付
- 图表丑陋/遮挡/无单位
- 摘要太空泛（无具体数字）
- 未做灵敏度分析（A 题尤其致命）

## 迭代方式
1. 先修第 0 层（优化闭环：可行性、范式切换、台账）——优化题最先查这里
2. 再修第①层（证据、数值、合规）——这是硬伤，不修必失分
3. 再按验收契约逐条核对（用户判定）
4. 最后处理第②层风格建议
5. 每轮修订后重新编译 PDF
6. 全部通过 + 用户确认 → 终止
