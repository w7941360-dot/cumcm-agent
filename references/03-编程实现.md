### 混合模式（各取所长）执行手册
> 调用时确认 `engine=python+matlab` 后自动按下述分工执行，无需逐步指定。

**分工原则（各取所长）**
| 工作类型 | 引擎 | 理由 |
|---|---|---|
| PDF/xlsx 解析、数据清洗、数据字典、JSON/manifest | Python | pandas/openpyxl 生态强 |
| 运行台账、结果汇总、resultN.xlsx 生成 | Python | CSV/Excel/JSON 好控制 |
| ODE/PDE、全局优化、布局优化、几何迭代、大规模数值 | MATLAB | ode45/pdepe/fmincon/particleswarm 稳且快 |
| 出图 | 跟随该问求解引擎 | 04 规范（求解与出图一致） |
| 独立交叉验证 | 另一引擎 | 双保险 |
| 画图脚本 | `code/plots/`（不进附录） | 附录只展示求解/模型代码 |

**每问默认分工模板**
- Q1 求值/仿真：Python 组织输入（CSV）→ MATLAB 核计算（ode45/pdepe）→ Python 读回、写结果
- Q2 参数辨识/优化：Python 准备数据与初始点 → MATLAB `fmincon`/`particleswarm`（可行性优先、硬约束进搜索）→ Python 读回、写 result2.xlsx
- Q3 多阶段/大规模：Python 批量生成输入/汇总 → MATLAB 逐核计算（多个小任务合并进一个 .m 一次跑完）→ Python 汇总
- 交叉验证：核心数值用另一引擎独立实现重算（MATLAB 结果用 scipy 复验，或反之）

**数据交换与纪律**
- 交换文件统一放 `data/processed/`：Python 写 `*.csv`（或 `.mat`）→ MATLAB 读入 → 写回 → Python 读
- **列名/单位/精度两侧对齐**，交接后两侧各验一遍；数值统一保留 6~8 位小数
- 每问引擎分配在步骤 1 写入全链路矩阵与 manifest（子问题级 `engine` 字段），中途不摇摆
- 复现命令在 `RESULTS.md` 写两段；`run_registry.json` 每次运行记录 `engine` 字段

## 运行治理与实验纪律（步骤 3 Type-A 项）
> 目标：每个实验可追溯、可断点续跑、不把"没跑完/空输出/被中断"当成完成。

### 运行台账 `code/run_registry.json`
每次实验写入一条记录（追加，不要覆盖）：

```json
{
  "run_id": "q2_par_b_03",
  "subproblem": "Q2",
  "config_hash": "sha256 前 8 位",
  "changed_assumption": "本轮回合相对上一轮唯一变化的假设",
  "paradigm": "范式名（与全链路矩阵一致）",
  "status": "ok | aborted | empty | failed",
  "duration_s": 1234,
  "result": {"P_full": 61.2, "feasible": true},
  "next_step": "refine 高度",
  "timestamp": "2026-08-13T10:00:00"
}
```

- **subproblem**：与全链路矩阵的子问题 id 一致（`scripts/solution_audit.py` 按它分组审计）
- **唯一配置 + 运行 ID**：每次实验使用独立配置文件与 `run_id`，禁止覆盖上一轮结果
- **一次只改一个假设**：每轮相对上一轮只允许一个 `changed_assumption`，保证因果可归因
- **状态纪律**：`aborted`（中断）/ `empty`（空输出）/ `failed`（报错）都是失败，**不得计为完成**；未完成运行不能生成带 `final` 命名的文件
- **断点续跑依据台账与结果有效性**：不是"文件存在=完成"，而是"台账该 run 状态为 ok 且结果非空"
- **路径可移植**：禁止在脚本中硬编码本机盘符或临时目录，一律从工作区根目录派生（`Path(__file__).resolve().parents[...]` 或环境变量）

### 单变量实验纪律
- 先估算单次成本与总预算（3~5 次 pilot），再决定扫描规模与 refine 次数上限
- 达到脚本数量或全模型评估预算上限后，**必须复盘范式**，不得继续堆变体
- 连续 N 轮（默认 3，可配）无可行候选 → 触发范式切换（回 `references/02-建模选型.md` 的求解治理、`references/07-改进循环.md` 的优化闭环）

## 数值实现要点
- ODE/PDE 求解：选稳定格式，检查 CFL/收敛；scipy.integrate 设 rtol/atol 并验证（MATLAB：ode45/ode15s/pdepe）
- 线性系统：注意条件数，病态时用正则化或提高精度
- 大量实验：写循环 + 进度日志 + 结果汇总表

## 结果可信度校验（每项都过）
1. **Sanity**：数量级合理吗？单位对吗？极端输入下行为合理吗？
2. **Consistency**：结果内部自洽（守恒量守恒、边界条件满足、不同方法结果一致）
3. **Physical**：物理约束满足（非负、有界、能量/质量守恒）
4. **Prediction**：外推一段是否合理？参数扰动方向是否符合直觉
5. **Evaluation**：与数据/解析解对比的误差指标（MAE/RMSE/相对误差）

## 优化过程专项验证（优化题必做，补充上面 5 项单次计算校验）
> 上面 5 项证明"单次物理计算可靠"，以下证明"优化过程可靠"。全部在 `run_registry.json` 与 `RESULTS.md` 中留痕。
- **搜索空间可行种子验证**：初始可行种子/理论上界由全模型复算
- **代理-全模型一致性**：排序相关性、可行性判定一致性（代理判可行/全模型不可行 = 假阳性）
- **多起点/随机种子稳定性**：不同随机种子与多起点收敛到同一可行域
- **约束边界复算**：最优解在硬约束边界处逐项复核（最小间距、禁镜区、场界、工艺窗口等）
- **理论上界夹逼**：计算结果 vs 解析/简化上界（上界 < 额定目标 = 搜索空间无解的证据）
- **范式公平对比**：不同范式在相同计算预算与相同全模型精度下对比，不拿代理比全模型
- **高精度复验**：最佳可行解在更高精度模型下重算，并留出误差安全裕量 ΔP
