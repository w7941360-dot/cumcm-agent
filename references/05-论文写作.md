# 05 论文写作

> 本章结构、措辞规范已按 2025 国赛 A 题实战反馈（FEEDBACK.md 12 条）重构。写作前读模板 `templates/paper/main.tex`，其章节骨架即本章要求。

## 结构与章节规范

### 摘要（≤1 页，最重要）
- 结构：**背景段 + 每个问题各一段 + 关键词行**（无英文翻译）
- 每问段落**七要素**：
  1. 情形及与前问关系（基础/拓展）
  2. 建模（决策变量 + 目标函数）
  3. 算法点名 + 亮点
  4. **最优策略数值（6~8 位小数）**——如 1.391643、4.587300
  5. 结果
  6. 交叉验证/相对误差
  7. 附件说明（措辞：「其余数据见附件 result1.xlsx」）
- 若首问有数学前置结论（如区间连续性、判定简化引理），在摘要前给出证明要点
- ⚠️ **全程禁止「结果填入 resultX.xlsx」这类话术**（指"把某结果写进表格"的流程性表述，不是"数据见附件"）

### 问题重述
- 固定结构：一、问题重述 → 1.1 问题背景 → 1.2 问题提出
- 1.1 背景：物理原理/工程背景 + 实际价值 + 本文任务总述
- 1.2 提出：先总述已知条件，再**按本质归类**子问题（如：单机单弹求值→优化；多弹时序规划；多机空间协同；任务分配+资源调度）
- 1.2 的五个子问题直接用「问题一：」「问题二：」…文本编号（\noindent\textbf{问题一：}… 或 \begin{itemize}[label={}]）；**不要**用 enumerate 自动编号，否则会出现「1. 问题 1」这类重复编号
- 全部用建模化措辞，禁写填表话术

### 问题分析（总体分析 + 逐问五步法 + 数值佐证；2024A 复盘升级）
- 二、问题分析 = **2.1 总体分析 + 2.2~2.6 逐问分节**（不再整段混写；整体篇幅建议 1.5~2 页，受当年正文页数上限约束）
- 节首放 **全题技术路线图**（整卷 1 张：逐问分步路线总览，标注难点与突破点）；每节配 1 张**解题路径流程图**
- ⚠️ 常见败笔：逐问只复述"求解路线/步骤"，缺"机理层为什么"与"量级佐证"→ 章节单薄、像流程清单。以下范式把这两点设为硬要求。

#### 2.1 总体分析（新增分节，三段式，必写）
1. **本质归类**：一句话把题目归入系统类型并点明"落点"。模板句："本题在本质上是一个'<系统>'的<类型>问题：<对象与约束>……；落点不是<单点/局部>描述，而是<系统级统一求解>。"若题目可被更简单模型近似，说明**为什么不能降维**（丢掉哪个约束/量会失真）。
2. **核心矛盾/耦合主线**：列 2~4 条决定建模路线的本质矛盾或耦合，每条 = "一句话机理 + 对应建模手段"，主线数量 = 后文模型模块数，保证"分析→模型"一一对应。
3. **量级观察与风险锁定**：用题给数据做量级估算（总长/跨度/间隙与尺寸对比/时间尺度/数量级），**预测**关键现象（如"必然碰撞""必然存在最优""约束在 XX 段活跃"），并在后文结果处呼应（闭环）。
4. （可选）**分层结构与递进关系**：点明子问题信息流（求值→事件→优化→新几何→反问题）与复用关系，为技术路线图做文字铺垫。

#### 逐问分析：四步法 → 五步法
每节固定五步，缺"③机理为什么"或"数值佐证"即为未完成：
1. ① 与前问关系（复用哪个内核、新增什么）
2. ② 分步求解路线（操作步骤，简写）
3. ③ **机理层"为什么"**（新增）：回答"为什么必须这样建 / 为什么危险发生在那里 / 为什么这个量是关键"，给本质原因而非步骤复述
4. ④ 本问特有难点（数值/几何/语义/无解预案）
5. ⑤ 落点（建立什么模型、输出什么）
6. （推荐）**数值佐证**：用题给参数或已算结果给 1 句量级佐证，让分析"有数据支撑"

#### 跨题型分析角度清单（A/B/C 通用，逐问对照打勾）
- [ ] 本质归类：这题是什么系统？（链/网络/场/队列/调度/统计回归/时序）
- [ ] 反直觉约束：哪条约束与直觉相反（欧氏 vs 弧长、离散 vs 连续、全局 vs 局部）→ 它决定建模手段
- [ ] 守恒/不变量：有什么量守恒（投影/能量/动量/总量）→ 可用于递推、判定、证明与简化
- [ ] 极端情形：参数→0/∞、边界、退化构型 → 判断危险态/可行性/单调性（决定"只看边界是否够"）
- [ ] 量级对比：关键尺寸/时间/数量级对比 → 锁定主导机制
- [ ] 递进与复用：子问题间依赖与信息流 → 分层结构与统一内核
- [ ] 反问题视角：约束→上限/下界 的转化（如多约束→单包络极值）
- [ ] 现象预测→数值佐证：先预测现象，再用题给数据或初算结果佐证（闭环）

#### 质量门禁（写作自查，未过不得进步骤 7）
1. 总体分析是否回答了：本质？几条主线？量级锁定了什么风险？
2. 每问是否有"机理层为什么"（不是操作步骤复述）？
3. 是否至少 1 处数值/量级佐证？
4. 分析提到的每条主线/模块，后文模型章是否都有对应？

### 符号说明
- **删除表名（caption）与表号、label**（正文不引用该表，删 label 安全）
- **每个符号单独一行**，禁止同一行放两个符号

### 模型准备（新增章，必须有）
- 顺序：**坐标系 → 态势可视化+观察分析 → 全题工作机理示意图 → 运动轨迹方程 → 关键判定条件（判定式）**
- 态势图是「观察→动机→算法」的起点，先画图再建模
- **全题工作机理示意图**（整卷至少 1 张）：交代题目整体工作原理——能量流/光路/受力/信息流/时序，让读者一眼看懂「系统怎么运转」，可并入态势图

### 模型建立与求解
- 每问设**副标题**（\subsection），不必每问单独大标题（\section）
- **建模四段式**：①情形及与前问关系 ②决策变量与目标函数 ③约束条件 ④建立公式并给出**推导过程**
- **公式推导过程必写**：从物理机制/几何关系/守恒律出发逐步推导，交代每一步依据（守恒、几何投影、近似、量纲），**禁止只贴最终公式**；推导过长时主线放正文、中间步骤进附录
- **思考过程逐步展示**：变量定义 → 目标函数 → 约束 → 推导依据，逐步交代，禁止只给「最终模型」；优化模型可按需采用「目标函数 + s.t. + 大括号约束组」排版
- 每问模型建立配 **1 张工作机理示意图**（该问的机制/几何/能量流局部图），与推导过程互相印证
- **求解三段式**：①算法（点名+亮点 + **算法流程图**）②数值求解 ③结果与分析
- 数值结果保留 6~8 位小数

#### 优化模型展示示例（s.t. + 大括号）
```latex
\begin{align}
\max_{x}\quad & f(x) \\
\text{s.t.}\quad & \left\{
\begin{array}{ll}
g_i(x)\le 0, & i=1,2,\dots,m,\\[2pt]
h_j(x)=0, & j=1,2,\dots,n,\\[2pt]
x\in \mathcal{X}.
\end{array}
\right.
\end{align}
```


### 优化题写作（含额定指标/设计变量的题）
- **搜索空间推导先行**：正文交代决策变量与范围从何推导（几何避挡/守恒律/工艺窗口），不写「经验扫描得到」
- **范式对比**：至少一段交代基线范式 vs 推导型范式的公平对比（同精度/同预算），淘汰依据写清
- **可行性优先叙述**：先写「是否满足额定指标（含安全裕量 ΔP）」，再写「可行解中谁最优」；不可行候选不进结果表
- **安全裕量表达**：给出模型误差来源与 ΔP 取值依据，避免「刚好达标」的观感
- **不声称全局最优**：写「固定随机种子得到的可行优选方案」+ 收敛性/多起点证据，不写「已证明全局最优」

### 模型评价
- **保留模型检验**（灵敏度/稳定性/误差单独成章）
- **优点条数 > 缺点条数**
- 用**文字分节陈述**（优点/缺点/推广），不在模板默认插入表格；确有必要时（多方案/多维对比）才用三线表
- 缺点用**「代价型」措辞**（如「以……计算代价换取……」「在……假设下适用」），不写自我贬低

### AI 工具使用声明（参考文献之前，国赛规定）
- **必须有**：放在参考文献前，单独一节，不编序号（`\section*`），内容从「未使用 / 使用 AI」二选一。
- 本 skill **默认使用 AI**，写：「本参赛队在竞赛过程中使用了AI工具，主要用于【实际用途：语言润色 / 代码调试 / 模型与代码框架整理 / 图表与流程示意图生成等】，详细使用情况见支撑材料。」
- 也可写成声明段并与参考文献对应：`\noindent\textbf{声明：}本参赛队在竞赛过程中使用了 AI 工具（DeepSeek-V4-Flash 大语言模型\cite{<ai-key>}），主要用于语言润色、代码调试和排版等，详细使用情况见支撑材料。`；并**同步在参考文献中加入所用 AI 模型条目**（版本型号与实际使用一致）。
- 若确未使用 AI，改为：「本参赛队在竞赛过程中未使用任何AI工具。」
- 使用 AI 的还须在**支撑材料**含 `AI工具使用详情.pdf`（模板见 `templates/AI工具使用详情.md`，规定见 `references/13-AI工具使用规范.md`），并在附录 A 支撑材料目录中注明。

### 参考文献
- 只保留 `thebibliography`，删除多余标题/官网/组委会条目
- **不少于 8 条学术文献**（期刊/会议论文）
- **每条至少被正文 `\cite` 一次**（用 compliance_check.py 自动检查）
- 引用必须真实存在，禁止编造（可用 arxiv/scholar 核实）
- 参考文献**限定近十年**（近 10 年内发表）为主；确需引用经典/奠基性文献（如算法原始文献）时，可少量保留并说明其为经典文献
- 若使用了 AI 工具，参考文献中加入所用 AI 模型的版本说明条目（如 DeepSeek-V4 技术报告：DeepSeek-AI. DeepSeek-V4: Towards Highly Efficient Million-Token Context Intelligence[J/OL]. arXiv:2606.19348, 2026.），并在正文声明处用 \cite 引用同一 key

### 附录
- 标题「附录」**不编序号**（\section*）
- **A 支撑材料目录**：源程序、中间图表、结果数据清单
- **B 代码（Python / MATLAB）**：展示支撑材料（`materials/源程序/`）中的**每问求解代码 + 模型代码**，**不含生图代码**（画图脚本统一放 `code/plots/` 或命名 `plot_*.py` / `fig_*.py` / `draw_*.m`，`collect_materials.py` 自动排除）；不能只列文件名或行段；每个文件一个小节注明**代码名**，代码用 listings **逐行标明行号**（`\lstinputlisting{../code/xxx.py}`；PDF 用 listings 自动行号，Word 由 pandoc 转换后人工核对行号与完整性；也可直接用 `collect_materials.py` 生成的 `附录B_代码表格.md` 以表格方式粘贴；每个子问题代码独立可运行（如 `problem1.py`），共享代码按功能命名（如 `data_io.py`）并可分多文件，不展示一键 main；附录代码可保留**适量中文注释**（关键公式/算法步骤），便于评委阅读）

## 图表使用（插入时机与规范见 references/04-图表规范.md）
- 问题分析：每问用 1 张解题路径流程图，标注难点与突破点
- 模型准备：态势/坐标系图先行，**先画图再建模**
- 每问求解：算法流程图 + 核心结果图/表「三位一体」
- 模型检验/灵敏度：参数扰动曲线、热图、Tornado 图、误差/残差图
- 模型评价：优点/缺点/推广用**文字分节陈述**，不默认插表格；仅当确有「多方案对比」价值时才用三线表
- **图表节制**：图前有引导、图后有解释；正文解释文字明显多于图表；连续图表间必须有文字
- 结果段写法：① 计算设置/参数来源 → ② 解析基线 → ③ 放核心数值表格/图 → ④ 比较解析与数值一致性 → ⑤ 文字解释数值含义 → ⑥ 回答题目要求 → ⑦ 补误差/稳定性/局限
- 每张核心图表后必须有一段解释文字，至少回答：图表展示什么、关键数值/趋势、支撑哪句结论、是否与基线或验证结果一致
- 数据怎么得出的，在正文简要说明即可（如「由 XX 计算/仿真得到」「基于表 X」）；**不必**为每张图单独建立数据存储文件


- A4 白纸，四边页边距 ≥ 2.5cm
- 摘要（含「摘要」标题与关键词）≤ 1 页
- 正文（不含参考文献与附录）≤ 30 页，25 页最好
- 页码：页脚**中部**，阿拉伯数字**从摘要页 1 连续编号**
- 页眉：无多余内容；页号只在页脚中部
- 汉字编号的一级标题（一、问题重述…）居中；「参考文献」标题也居中（\section*{参考文献} 用 \centering 或 \begin{center}…\end{center}）
- 所有图表居中（\centering）；图注尽量中文
- 图内文字/图例间距合理，不拥挤不重叠

## 摘要五句公式（ARIS，辅助记忆）
1. 你完成了什么 2. 为什么重要且困难 3. 你怎么做的 4. 什么证据支撑 5. 读者该记住什么数字
（七要素是国赛逐问版，比五句更细，以七要素为准）

## 写作原则（句子层面）
- 主语谓语靠近；新信息放句末；上下文放句首；从旧到新；一个单元一个功能；动作放动词里
- 目标不是显得高深，而是让读者跟得上论证；假设先于公式；符号全篇一致、首次使用即定义
- 匿名：不出现姓名、学校、指导教师
